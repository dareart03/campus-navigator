# Навигатор по корпусу

Индивидуальный проект (тема 12): веб-приложение, которое показывает план трёхэтажного корпуса и строит кратчайший маршрут между двумя аудиториями, в том числе между этажами.

Статический сайт без фреймворков: HTML + JS (ES-модули), карты в SVG, граф здания в JSON, поиск пути — алгоритм Дейкстры.

## Запуск

Страница загружает файлы через `fetch`, поэтому открывать `index.html` двойным щелчком нельзя — нужен локальный сервер:

```powershell
python tools/serve.py
```

- на компьютере: <http://localhost:8000>
- на телефоне (в той же Wi-Fi сети): `http://<IPv4 компьютера>:8000` (адрес печатает сам `serve.py`)

## Точки интереса и ссылка на маршрут

- Выберите старт, затем нажмите **«Туалет (М)»**, **«Туалет (Ж)»**, **«Выход»** или **«Столовая»** — маршрут построится до ближайшего такого места по длине пути (в том числе на другом этаже).
- Под шагами маршрута: **QR-код**, **Копировать ссылку** и (где поддерживается) **Поделиться**. Ссылка вида `?from=f3-room-311&to=f1-exit-1` открывает приложение сразу с этим маршрутом; адресная строка всегда показывает текущий маршрут.
- Выходы рисуются в SVG линиями в группе `Doors` с id `door-exit-1`, `door-exit-2`, туалеты — группами `man-WC-1`, `woman-WC-2`, `special-WC`; столовая — `room-dining room`.

## Как пользоваться

1. Выберите этаж кнопками сверху.
2. Нажмите на аудиторию — она станет **стартом** (зелёная обводка).
3. Нажмите на другую аудиторию (можно на другом этаже) — построится **маршрут**, а под картой появятся шаги: «Этаж 3: от аудитории 311 до лестницы → Спуститесь на 2 этаж → …». Нажатие на шаг переключает карту на нужный этаж.
4. Начать можно и **с фото**: кнопка «📷» рядом с поиском → «Снять» или «Из галереи» → нажмите на найденное место, и оно станет стартом (см. раздел «Старт по фото двери»).
5. Сбросить маршрут: кнопка «✕ Сбросить маршрут», повторное нажатие на стартовую аудиторию или `Esc`.

Жесты на карте: перемещение — один палец; масштаб и поворот — щипок двумя пальцами; двойное нажатие — приблизить / вернуть вид; кнопка «⌖ Вид» — исходный вид. На компьютере: колесо мыши — масштаб, `Shift` + колесо — поворот.

## Модель данных

`data.json` — один граф на всё здание:

- **узлы** `{id, x, y, floor, type, label}`; `type`: `room`, `door`, `corridor`, `stairs`, `wc`;
- **рёбра** `{from, to, weight, type}`; вес — длина в пикселях карты;
- id содержат этаж: `f3-room-311`, `f2-ladder-1`;
- лестницы одного номера на соседних этажах соединены рёбрами типа `stairs`;
- аудитории — только начало или конец маршрута, сквозь них путь не идёт.

## Как обновить карту

Планы рисуются в векторном редакторе и экспортируются в SVG **с атрибутами `id`** (в Figma: настройки экспорта → *Include "id" attribute*). Нужные группы и имена слоёв:

- группы `corridor`, `Rooms`, `Ladders`, `Doors`, `Texts`;
- комнаты — `room-311`, двери — `door-311` (у комнаты несколько дверей — `door-325-1`, `door-325-2`), лестницы — `ladder-1…4`, двери лестниц — `door-ladder-1`.

Затем:

```powershell
pip install -r tools/requirements.txt
python tools/build_graph.py                              # maps/*.svg -> data/data.json
python tools/build_graph.py --debug-dir debug            # + картинки графа для проверки
python tools/build_graph.py --check f3-room-311 f1-room-103   # + пример маршрута
```

Скрипт находит коридоры, строит проходимую область, соединяет двери и углы видимостью, проверяет связность и выводит замечания (комната без двери, дверь не у комнаты и т. д.). Названия вроде `dining room` заменяются русскими через `tools/names.json`; значением может быть список: первое — основное название, остальные сохранятся как `aliases` (для будущего поиска).

## Тесты

```powershell
npm test
```

121 тест (`node --test`, без зависимостей):

- Дейкстра: кратчайший путь, недостижимая аудитория, запрет прохода сквозь комнату, неизвестный id;
- валидация `data.json` (дубли, висячие рёбра, неверные веса, расхождение с SVG);
- реальные данные трёх этажей: лестницы соединяют только соседние этажи, из любой аудитории достижима любая другая, маршруты 3 → 2 → 1 идут по порядку, выбирается ближайшая из нескольких дверей;
- математика жестов: точка под пальцами остаётся на месте при масштабе, повороте и щипке, границы масштаба и сдвига, размер подписей;
- ближайшее место: поиск в реальных данных сверяется с полным перебором, сквозь комнаты не ходим;
- компас: направление при лежащем, наклонённом и вертикальном телефоне (без скачка), переход через 0°/360°, знак поворота карты (проверено поворотом точки на экране), мусор вместо калибровки;
- строки текста: слово из нескольких букв — строка, одиночная буква и столбик — нет, строки одна под другой и буквы разного размера не склеиваются, крупная строка идёт первой;
- надписи: «Спортивный зал», кафедра, лаборатория (в т. ч. с мусором и ошибкой в букве), «Серверная» против общего текста, номер в «Раздевалка № 3» обязан совпасть, шапка института и пустой текст ничего не находят, одно слово «кафедра» ничего не находит, туалеты не ищутся;
- фото двери: поиск цифр на искусственных «снимках» (ряд из трёх цифр находится, одиночные пятна, лестница из цифр и разная высота — нет, телефон и год — нет), выбор номера по графу (несуществующий отбрасывается, две таблички усиливают друг друга, крупная рамка весит больше);
- экраны и состояние: адрес ↔ экран, «Назад», сохранённое состояние читается, мусор в хранилище отбрасывается по частям, недоступное хранилище не роняет запуск;
- отсечение за экраном и куча: обратная матрица, видимый прямоугольник при повороте, пересечения, «закреплённые» элементы, куча сортирует как `sort`;
- ссылка: сборка и разбор, битые ссылки, QR-код;
- поиск: номера, названия, синонимы, порядок слов, избранное, недавние, очистка устаревших данных, работа без `localStorage`.

## Производительность (T3)

**Поиск пути** — `node tools/bench.mjs` (медиана 15 запусков; прежний O(V²) против кучи, ответы сверяются):

| аудиторий | узлов | старый поиск | с кучей |
|---|---|---|---|
| 200 | 500 | 1,95 мс | 0,39 мс |
| 500 | 1260 | 11,7 мс | 0,29 мс |
| 2000 | 5000 | 246 мс | 1,5 мс |

**Отрисовка** — `bench/render.html` (150 кадров масштабирования, на каждом кадре меняется `--ls` у всех подписей, как в приложении). Работа главного потока за сценарий, 1000 аудиторий (3000 элементов):

| вариант | всего | пересчёт стилей | худший кадр |
|---|---|---|---|
| без отсечения | 2,44 с | 1,79 с | ~100 мс |
| `display: none` у невидимых | 2,25 с | 1,59 с | ~300 мс |
| удаление невидимых из DOM (используется) | 0,71 с | 0,36 с | ~30 мс |

Вывод из замера: простое скрытие почти не помогает (браузер всё равно пересчитывает стили у скрытых при смене `--ls`), поэтому невидимые комнаты, подписи и двери временно убираются из DOM, а на их месте остаётся пустой комментарий (порядок в SVG сохраняется). Выбранные старт и финиш не убираются. Реальный план (99 элементов) помещается в экран целиком, выигрыш виден при увеличении: `?stats=1` показывает «рисуется N из M», `?cull=0` отключает отсечение для сравнения.

## Компас (S2)

Датчик ориентации телефона поворачивает карту так, чтобы «вверх» экрана было там, куда вы смотрите.

- **Включить:** кнопка «🧭 Компас» под картой. На iPhone браузер спросит разрешение.
- **Калибровка (один раз):** «вверх» на плане у каждого здания смотрит в свою сторону света. Встаньте лицом туда, куда на карте направлено «вверх» (например, вдоль коридора, который нарисован вертикально), и нажмите «⬆ Задать «вверх»». Угол запоминается.
- **Двигаете карту пальцами** — компас на 3 секунды отступает, чтобы не мешать. Кнопка «Вид» выключает компас и возвращает карту.
- **Как устроено:** `compass.js` считает направление по углам датчика (работает и при лежащем, и при вертикальном телефоне), сглаживает его по кругу (359° и 1° дают 0°, а не 180°) и переводит в угол поворота вида карты. Дальше работает тот же поворот, что у жестов, поэтому подписи остаются прямыми.
- **Проверить на компьютере:** DevTools → ⋮ → More tools → Sensors → Orientation → Custom orientation, менять alpha. Если карта не реагирует, в этом браузере нет эмуляции датчика, тогда проверять на телефоне.
- **Ограничения:** работает только по https (на GitHub Pages — да; по `http://192.168…` — нет) и только на устройствах с датчиком; в здании со сталью возможны помехи; положение человека датчиками не определяется (GPS внутри не работает), поворачивается только карта.

## Старт по фото двери (S1)

**Как пользоваться.** «📷» рядом с поиском → «Снять» (камера) или «Из галереи» → кнопка «Начать отсюда: 116». Распознанное предлагается кнопкой, а не принимается молча: если снимок прочитан неверно, ошибка видна до того, как старт поставлен.

**Как устроено.** Читать фото целиком бесполезно: номер маленький, вокруг объявления, расписания и значки (проверено: Tesseract на целом кадре выдаёт мусор). Поэтому два этапа:
1. `signs.js` ищет места, похожие на номер: тёмное на светлом (порог по среднему в окрестности, интегральное изображение), связные области подходящего размера и пропорций, ряды из 3–4 цифр одной высоты. Занимает 10–20 мс.
2. `ocr.js` вырезает только эти рамки, приводит их к высоте 64 px и читает Tesseract (только цифры, одна строка). Распознавание идёт в веб-воркере, страница не зависает.

Потом `pickRoomNumber` выбирает число, которое есть в здании (`data.json`); на двери часто две таблички с одним номером (латунная и жёлтая) — их голоса складываются, крупная и уверенно прочитанная рамка весит больше. Числа из расписаний («ауд. 117») мелкие и в рамки не попадают; если попали, их перевешивает номер с таблички.

**Если номера нет, читаем надписи.** Нужно для кафедр, «Серверной», «Спортивного зала» и т. п. Целиком фото с надписями Tesseract читает плохо (не разбирается в раскладке на фоне дерева и бумажек; на первой версии так и вышло: на телефоне надписи почти не находились), поэтому тот же приём, что и с номером: `findTextLines` находит строки текста (тёмные буквы одной высоты в ряд), и каждая строка читается отдельно в режиме «одна строка» русской моделью. Самые крупные строки идут первыми, на всё отведено не больше 12 секунд. `names.js` сопоставляет прочитанное с названиями и синонимами из `data.json`: слова сравниваются по первым 6 буквам (падежи не мешают), допускаются обрывок слова и до двух ошибок OCR в длинном слове, редкие слова весят больше частых («серверная» — у одного места, «кафедра» — у десятка), нужно совпадение не меньше 60% веса названия. Цифра в названии («раздевалка 3») мелкая и часто не читается, поэтому её отсутствие только снижает оценку. Крупная надпись важнее мелкой бумажки: при равной оценке выше стоит место, слова которого прочитаны в более крупных строках. Если подходит несколько мест (например, одинаковая бумажка «Помещение для хранения…» у трёх комнат), показываются до трёх кнопок на выбор. Русский язык грузится только тогда, когда номера на фото не нашлось.

**Проверено на реальных снимках** (10 дверей, в браузере, эмуляция телефона): верно 118, 116, 109, 201, 212, 218, 303, 321. Без номера: «Спортивный зал» и «Раздевалка № 3 женская» (общий план коридора) находятся по надписи. Те же снимки с закрашенным номером: 201, 303 и 321 находятся по названию (321 — первой в списке вместе с двумя комнатами с такой же бумажкой, 218 — первой, вторым 201). Устойчивость проверена на копиях: поворот на 4°, уменьшение до 800 px, затемнение, размытие — надпись по-прежнему находится (на повёрнутом снимке 303 к ней добавляется ещё один вариант на выбор).

**Ограничения.**
- Нужна чёткая табличка без сильных бликов; на очень косых снимках цифры и строки могут не найтись, текст белым по тёмному не читается.
- Надписи читаются дольше номера (на компьютере 1–3 секунды, на телефоне дольше), поэтому запускаются, только если номера на фото нет.
- Первый запуск распознавания скачивает около 7 МБ (номера) и ещё около 3 МБ (надписи, при первом таком снимке), потом файлы лежат в кеше и работают без сети.
- Используется ядро с SIMD (есть в браузерах телефонов с 2021 года); без него распознавание не запустится, останется поиск.
- Фото обрабатывается на устройстве и никуда не отправляется.

## Работа без сети и темы

- Первый запуск нужен с сетью: service worker кеширует файлы при первом открытии (работает по https и на `localhost`; по `http://<IP>` в локальной сети регистрироваться не будет — это ограничение браузеров).
- Онлайн всегда берутся свежие файлы, из кеша — только если сети нет.
- Страница `index.html` хранится в кеше под одним ключом, как бы её ни открыли («/», «/index.html», «/?from=…&to=…»). Раньше копии хранились под каждым адресом: онлайн обновлялась только та, с которой открыли, а офлайн по ярлыку отдавалась старая страница вместе с новым `app.js`, и приложение падало с ошибкой `Cannot read properties of null (reading 'addEventListener')`. Ошибка воспроизведена в браузере и исправлена; при выпуске новой версии меняется номер в имени кеша (`CACHE` в `sw.js`).
- Тема следует за системной (`prefers-color-scheme`). Проверить на компьютере: DevTools → ⋮ → More tools → Rendering → «Emulate CSS media feature prefers-color-scheme».
- Размер шрифта 1,3×: на Android — Настройки → Дисплей → Размер шрифта; на компьютере — Chrome → Настройки → Внешний вид → Размер шрифта.

## Известные ограничения

- проверка жестов выполнялась в эмуляции и на одном телефоне.
