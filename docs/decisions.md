# Технические решения (C11, C12)

[← К README](../README.md)

## Секреты и главный поток (C11)

**Секретов нет.** Приложение целиком работает в браузере: ни ключей API, ни токенов, ни паролей, ни своего сервера. Внешние сервисы не используются: библиотеки (QR-код, tesseract.js и его модели) лежат в репозитории в `src/vendor/` с лицензиями, а не подгружаются с чужих адресов. Проверка: поиск по репозиторию слов `key`, `secret`, `password`, `bearer` в коде ничего не находит (слово `token` встречается только как «слово названия» в поиске по названиям). В `.gitignore` стоят `.venv/`, `debug/`, `node_modules/` и `.vscode/`: личного окружения в коммитах нет.

**Долгие операции вне главного потока.**
- **Распознавание фото** (самое долгое: загрузка около 7 МБ модели, WebAssembly, сам OCR на секунды) выполняет tesseract.js в **веб-воркере** (`ocr.js`: `Tesseract.createWorker`). Интерфейс в это время отвечает: показывается «Распознаю…», карта и поиск остаются доступными.
- На главном потоке остаётся только лёгкая подготовка снимка (серое изображение, поиск рамок с цифрами, `signs.js`): порядка 20–90 мс на компьютере (замер в Node на кадре 960×720 и 1600×1200), на телефоне в несколько раз дольше, но это одна короткая задержка, а не секунды.
- **Поиск пути** занимает доли миллисекунды (0,3–1,5 мс на графах до 5000 узлов, см. T3), поэтому воркер ему не нужен: перенос в воркер добавил бы только накладные расходы на передачу графа.
- **Загрузка карт и графа** асинхронная (`fetch` + `await`), страница показывает индикатор загрузки.
- **Тяжёлая перерисовка при масштабировании** снижена отсечением невидимых элементов (T3, замеры в [docs/tests-and-performance.md](docs/tests-and-performance.md)).

## Почему так (C12)

| Решение | Почему так | Что отвергнуто и почему |
|---|---|---|
| Статический сайт, HTML + ES-модули, без фреймворка и сборщика | Приложение маленькое (один экран карты, три экрана навигации); код читается как есть, на защите можно показать, где что; GitHub Pages раздаёт файлы без сборки | React/Vue: лишняя зависимость и сборка ради нескольких экранов; нативное приложение: нужен магазин, а требуется открыть на телефоне по ссылке |
| Планы в SVG | Векторные: не мутнеют при масштабе, комнаты и подписи уже элементы со своими `id`, на них можно нажимать без расчёта попаданий; рисуются в обычном редакторе | Растровые картинки: размытие и ручная разметка областей; Canvas: нужно самим считать попадание и перерисовывать; тайловая карта: избыточна для одного здания |
| Граф в JSON, генерируется из SVG скриптом | Карту рисует человек, граф строится автоматически (`build_graph.py`): меняется план, перезапускается команда; приложение читает готовый граф и не считает геометрию на телефоне | Рисовать граф вручную: ошибки и расхождения с картой; считать геометрию в браузере: тяжело и медленно на слабом телефоне |
| Дейкстра на бинарной куче | Нужны кратчайшие пути с разными весами рёбер; на графе в сотни узлов ответ за доли миллисекунды (замеры T3: 246 мс → 1,5 мс на 5000 узлов против простого поиска). Для реального здания хватает с большим запасом | Поиск в ширину: не учитывает длины; A*: нужна эвристика, а между этажами прямая линия ничего не значит (лестницы), выигрыша на таком графе нет |
| Вес лестницы 200 | Измерено: при 40 «ближайший туалет» выбирался этажом ниже в 30 случаях из 122; этаж = два пролёта, это порядка 12–15 м ходьбы, и идти по лестнице медленнее | Запрет прохода по лестнице при поиске туалета: сломал бы маршруты, когда туалета на этаже действительно нет |
| Аудитории не проходные | Сквозь комнату люди не ходят: комната только начало или конец маршрута | Рёбра через комнаты: маршруты «сквозь стену» |
| Отсечение невидимых элементов удалением из DOM | Замер: `display: none` почти не помогает (стили всё равно пересчитываются), удаление из DOM даёт 0,71 с против 2,44 с | Оставить как есть: на плане с 1000 аудиторий лагает; виртуализация библиотекой: лишняя зависимость |
| Жесты на Pointer Events, математика отдельно (`viewmath.js`) | Один API для мыши и пальцев, математика без DOM проверяется тестами (точка под пальцами остаётся на месте при масштабе и повороте) | Hammer.js и подобные: зависимость, поворот и масштаб всё равно считать самим |
| Распознавание фото на устройстве (tesseract.js, свои поиск рамок и сопоставление с графом) | Работает без сети, фото не уходит на чужой сервер (приватность, нет ключей), номер выбирается по графу: несуществующие числа отбрасываются | Облачный OCR: ключи и расходы, утечка снимков; встроенное распознавание текста в браузерах: нет стабильной поддержки; OCR целого кадра: на реальных фото почти не читал, поэтому поиск рамок и построчное чтение |
| Библиотеки лежат в репозитории (`src/vendor/`) | Работает офлайн, версия зафиксирована, нет зависимости от доступности чужих адресов | CDN: без сети не запустится, версия может измениться |
| Service worker «сначала сеть, при неудаче — кеш» | Онлайн всегда свежие файлы (удобно при правках), офлайн работает последняя копия | «Сначала кеш»: можно застрять на старой версии после правок |
| `sessionStorage` для вида карты, `localStorage` для избранного | Положение карты нужно после перезагрузки, но не через неделю; избранное и недавние должны жить долго | Всё в `localStorage`: через неделю приложение открывалось бы в прошлом масштабе |
| Компас на углах датчика с калибровкой «куда смотрит верх плана» | В здании нет лифтов, ориентироваться важно при подъёме по лестнице; у каждого здания «вверх» на плане смотрит в свою сторону света | Считать север из геолокации: в здании не работает |
| Число этажей из `data.json`, не из кода | Новое здание с другим числом этажей подключается без правки кода | Список `[1, 2, 3]` в коде: ломается на другом здании (так и было) |
| `run.py` одной командой | Чистый клон запускается без скрытых шагов за минуту | Длинная инструкция из пяти команд: легко пропустить шаг |
